🔹Unit I: 80386 Architecture, Instruction Set & Memory Management

Overview & Key Features of 80386 Microprocessor

The Intel 80386 (i386) is a 32-bit microprocessor that introduced 32-bit processing, advanced memory management, and hardware-level multitasking to the x86 architecture.

  • 32-Bit Processing Engine: Features a 32-bit Arithmetic Logic Unit (ALU), 32-bit internal registers, a 32-bit data bus, and a 32-bit non-multiplexed address bus.
  • Addressing Capability:
    • Physical Address Space: \(2^{32}\) bytes = 4 GB.
    • Virtual Address Space: \(2^{46}\) bytes = 64 TB (\(16,384 \times 4\text{ GB}\)).
    • Maximum Segment Size: 4 GB.
    • I/O Ports: Up to 64 K (\(65,536\)) 8-bit I/O ports.
  • Operating Modes:
    1. Real Mode: Default power-up mode; behaves as an enhanced 8086 with a 1 MB physical memory limit.
    2. Protected Mode: Native 32-bit mode enabling 4 GB physical memory, virtual memory, 4-level privilege protection, segmentation, and paging.
    3. Virtual 8086 Mode: A sub-mode of Protected Mode that allows execution of 16-bit real-mode software within a protected, paged environment.
  • Clock Frequency & Packaging: Operates at 16 MHz, 20 MHz, 25 MHz, and 33 MHz frequencies in 132-pin or 100-pin packages.
  • Data Type Support: Supports 17 different data types ranging from bit arrays and BCD numbers to 32-bit integers and floating-point types via the 80387 math coprocessor.

1. Central Processing Unit (CPU)
  • Execution Unit (EU): Contains eight 32-bit General Purpose Registers (GPRs) and eight special-purpose registers. It features a 64-bit Barrel Shifter capable of shifting data words by multiple positions in a single clock cycle without sequential delays. The hardware multiply/divide logic uses bit-shift-rotate algorithms to accelerate arithmetic operations (e.g., executing a 32-bit integer multiplication in \(1\text{ }\mu\text{s}\)). The Control ROM stores microcode sequences that define complex machine instructions.
  • Instruction Unit (IU): Receives raw opcode bytes from the 16-byte Instruction Prefetch Queue, decodes them via the Instruction Decoder, and feeds a 3-decoded instruction queue for output to the Execution Unit.
2. Memory Management Unit (MMU)
  • Segmentation Unit: Translates logical addresses (consisting of a 16-bit Segment Selector and a 32-bit Offset) into a 32-bit Linear Address. It houses Descriptor Registers, a 3-input Adder, and a Limit and Attribute PLA that verifies access rights and segment limits (up to 4 GB) against the 4-level privilege model.
  • Paging Unit: Converts 32-bit linear addresses into 32-bit physical addresses when paging is enabled (PG = 1 in CR0). It partitions memory into fixed-size 4 KB pages. Its internal Control and Attribute PLA manages page-level privileges, while a Translation Lookaside Buffer (TLB / Page Cache) caches recently used page table entries.
3. Bus Interface Unit (BIU)
  • Request Prioritizer: Resolves access priorities between prefetch commands, internal data transfers, and external bus master signals (HOLD, INTR, NMI, RESET, HLDA).
  • Address Driver: Drives address lines A2–A31 and Byte Enable outputs (BE0#–BE3#).
  • Pipeline / Bus Size Control: Controls dynamic bus sizing (BS16#), address pipelining (NA#), write/read differentiation (W/R#), control signaling (D/C#, M/IO#), and bus lock operations (LOCK#).
  • MUX / Transceivers: Interfaces the 32-bit internal data bus with external lines D0–D31.

80386 Hardware Signal Definitions

  • W/R# (Write/Read): Distinguishes between write cycles (1) and read cycles (0).
  • D/C# (Data/Control): Distinguishes between data transfers (1) and control cycles (0).
  • M/IO# (Memory/IO): Distinguishes memory accesses (1) from I/O port accesses (0).
  • LOCK#: Prevents other bus masters from gaining system bus control during atomic operations.
  • NA# (Next Address): Input signal asserted by external memory circuits to request address pipelining.
  • ADS# (Address Status): Output signal indicating that valid addresses (A2–A31, BE0#–BE3#) and bus cycle definitions (W/R#, D/C#, M/IO#) are active on the bus.
  • READY#: Bus termination signal from memory or I/O. Inserting low states adds WAIT states for slower peripherals.
  • BS16# (Bus Size 16): Converts the 32-bit bus to a 16-bit bus for interfacing with 16-bit hardware components.
  • HOLD & HLDA: Bus Hold Request and Bus Hold Acknowledge signals for Direct Memory Access (DMA).
  • BUSY#, ERROR#, PEREQ: Coprocessor handshaking signals for the 80387 Math Coprocessor. BUSY# signals active operations, ERROR# signals floating-point exceptions, and PEREQ requests data word transfers.

1. General-Purpose Registers (GPRs)

Eight 32-bit registers (EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP).

  • The lower 16 bits of each register form legacy 16-bit registers (AX, BX, CX, DX, SI, DI, BP, SP). Operations on 16-bit sub-registers preserve the upper 16 bits.
  • AX, BX, CX, DX split into 8-bit byte registers (AH/AL, BH/BL, CH/CL, DH/DL).
2. Segment Registers

Six 16-bit registers storing Segment Selectors:

  • CS (Code Segment): Points to execution code descriptors.
  • SS (Stack Segment): Points to the active call stack descriptor.
  • DS, ES, FS, GS (Data Segments): Point to active data segment descriptors.
3. Instruction Pointer & EFLAGS
  • EIP (Extended Instruction Pointer): 32-bit register containing the instruction offset relative to the base address of the Code Segment (CS). Lower 16 bits are accessed as IP.
  • EFLAGS Register: A 32-bit control and status register.

  • RF (Bit 16 - Resume Flag): Temporarily disables debug breakpoint faults on the subsequent instruction execution. Resets automatically.

  • Status Flags: OF (Overflow), DF (Direction), IF (Interrupt), TF (Trap), SF (Sign), ZF (Zero), AF (Auxiliary Carry), PF (Parity), and CF (Carry).
4. Control Registers

Four 32-bit registers (CR0, CR1, CR2, CR3) that define global machine states:

  • CR0 (Machine Control Register):
    • PE (Bit 0 - Protection Enable): 1 switches the CPU to Protected Mode; 0 forces Real Mode.
    • MP (Bit 1 - Monitor Coprocessor): Controls coprocessor interaction together with TS.
    • EM (Bit 2 - Emulate Coprocessor): Setting 1 forces software emulation of math coprocessor instructions via software interrupts.
    • TS (Bit 3 - Task Switched): Automatically set on task switch; delays coprocessor state saving.
    • ET (Bit 4 - Extension Type): Indicates math coprocessor type (1 = 80387, 0 = 80287).
    • PG (Bit 31 - Paging Enable): 1 enables the internal paging MMU; 0 disables paging.
  • CR1: Reserved for future processors.
  • CR2 (Page Fault Linear Address): Holds the 32-bit linear address that triggered the most recent Page Fault exception.
  • CR3 (Page Directory Base Register - PDBR): Holds the physical base address of the Page Directory table (upper 20 bits).
5. System Address Registers
  • GDTR (Global Descriptor Table Register): 48-bit register storing the 32-bit base address and 16-bit table limit of the GDT.
  • IDTR (Interrupt Descriptor Table Register): 48-bit register storing the 32-bit base address and 16-bit limit of the IDT.
  • LDTR (Local Descriptor Table Register): 16-bit selector referencing an LDT descriptor stored in the GDT.
  • TR (Task Register): 16-bit selector pointing to the active process’s Task State Segment (TSS) descriptor within the GDT.

Descriptor Tables
  1. Global Descriptor Table (GDT): System-wide table containing memory descriptors for all shared tasks and operating system components.
  2. Local Descriptor Table (LDT): Task-specific table providing isolated descriptor spaces for individual applications.
  3. Interrupt Descriptor Table (IDT): Contains 256 8-byte entry gates (Task Gates, Interrupt Gates, Trap Gates) handling hardware/software interrupts.
  4. Task State Segment (TSS) Descriptor: Points to a dedicated memory block storing saved register contexts (EAX, EBX, ECX, EDX, EBP, ESP, EIP, EFLAGS, Segment Registers), stack pointers for Ring 0, 1, and 2, and the I/O Permission Bitmap for multitasking.

Memory Protection Mechanisms

The 80386 enforces hardware-level security through privilege ring levels and page access rights.

  1. Privilege Levels (Rings 0–3):
    • Ring 0 (Most Privileged): Operating System Kernel.
    • Rings 1 & 2: System Services and Device Drivers.
    • Ring 3 (Least Privileged): User Application Programs.
  2. Privilege Checking Rules:
    • CPL (Current Privilege Level): Stored in bits 0-1 of the CS register.
    • RPL (Requested Privilege Level): Stored in bits 0-1 of a Segment Selector.
    • DPL (Descriptor Privilege Level): Defined in the target Segment Descriptor.
    • Data Access Rule: A program at level CPL can access data segments only if \(\max(\text{CPL}, \text{RPL}) \le \text{DPL}\).

    • User/Supervisor (U/S): 0 restricts access to Ring 0-2 (Supervisor); 1 allows Ring 3 (User) access.
    • Read/Write (R/W): 0 restricts memory to Read-Only; 1 permits Read/Write access.

Addressing Modes & Instruction Parsing

The effective memory address in the 80386 is computed using the expression: \[\text{Effective Address} = \text{Base Register} + (\text{Index Register} \times \text{Scale Factor}) + \text{Displacement}\] Where Scale Factor \(\in \{1, 2, 4, 8\}\).

Common Addressing Modes with Examples
  1. Immediate Mode: Operand is a constant embedded within the instruction opcode.
    • Example: MOV EAX, 12F3H \(\rightarrow\) Loads 000012F3H into register EAX.
  2. Register Direct Mode: Operands reside inside internal registers.
    • Example: ADD EAX, EBX \(\rightarrow\) Computes EAX = EAX + EBX.
  3. Direct Mode: Offset address is specified directly as a constant in the instruction.
    • Example: MOV AL, [1234H] \(\rightarrow\) Reads byte located at memory address DS:1234H into AL.
  4. Register Indirect Mode: Address is contained in a base/index register.
    • Example: MOV ECX, [EAX] \(\rightarrow\) Reads 32-bit double-word at memory address referenced by EAX.
  5. Based Relative Mode: Address formed by summing a base register with a constant displacement.
    • Example: MOV AL, [BX + 1234H] \(\rightarrow\) Target address = DS:[BX + 1234H].
  6. Indexed / Based-Indexed Mode: Address formed by summing base and index registers.
    • Example: MOV EDX, [EBX + EDI] \(\rightarrow\) Target address = DS:[EBX + EDI].
  7. Scaled Indexed Mode: Includes a scaling multiplier (\(1, 2, 4, \text{or } 8\)) applied to the index register.
    • Example: MOV ECX, [EAX + 24] \(\rightarrow\) Target address = DS:[EAX + 24].

PYQ 1: Logical Address Translation

Question: If the logical address after segmentation is 0202007AH, calculate:

  1. Page Directory Index
  2. Page Table Index
  3. Offset within Page
  4. Page Directory Entry (PDE) address if CR3 contains 00030000H.

Step-by-Step Solution: Convert the 32-bit linear address 0202007AH into binary: 0202007AH = 0000 0010 0000 0010 0000 0000 0111 1010 B

Split into Paging Fields:

  • Directory Index: Bits 31–22 (10 bits)
  • Table Index: Bits 21–12 (10 bits)
  • Page Offset: Bits 11–0 (12 bits)
Binary Split:
[0000 0010 00] [00 0010 0000] [0000 0111 1010]
   Bit 31..22     Bit 21..12     Bit 11..0
  1. Directory Index Calculation:
    • Binary: 0000 0010 00 B = 008H = 8 (Decimal).
  2. Table Index Calculation:
    • Binary: 00 0010 0000 B = 020H = 32 (Decimal).
  3. Offset in Page Calculation:
    • Binary: 0000 0111 1010 B = 07AH.
  4. Page Directory Entry (PDE) Address Calculation:
    • Since each descriptor entry occupies 4 bytes: \[\text{PDE Address} = \text{CR3 Base Address} + (\text{Directory Index} \times 4)\] \[\text{PDE Address} = 00030000\text{H} + (8 \times 4) = 00030000\text{H} + 32 = 00030000\text{H} + 20\text{H} = \mathbf{00030020\text{H}}\]
PYQ 2: Linear Address Translation

Question: If the linear address is 012AB127H, explain how to locate PDE, PTE, and Page Frame using the paging mechanism.

Step-by-Step Solution: Convert 012AB127H to binary: 012AB127H = 0000 0001 0010 1010 1011 0001 0010 0111 B

Bit Segmentation:

[0000 0001 00] [10 1010 1011] [0001 0010 0111]
  Bits 31-22     Bits 21-12     Bits 11-0
  1. Directory Index (Bits 31-22): 0000 0001 00 B = 004H (4 Decimal).
    • The MMU multiplies 4 by 4 bytes = 16 (10H), adding it to the base address in CR3 (Page Directory Base Address) to select PDE #4.
  2. Table Index (Bits 21-12): 10 1010 1011 B = 2ABH (683 Decimal).
    • The fetched PDE yields the base address of the target Page Table. The MMU multiplies 683 by 4 bytes = 2732 (ABCH) and adds it to the Page Table Base Address to locate PTE #683.
  3. Page Frame Offset (Bits 11-0): 0001 0010 0111 B = 127H.
    • The PTE yields the physical base address of the 4 KB Page Frame. Concatenating this base address with the offset 127H accesses the exact physical byte.

Fast Adders & Signed Number Arithmetic

  • Carry-Lookahead Adder (CLA): Reduces latency compared to ripple-carry adders by generating carry signals in parallel using bit logic:
    • Carry Generate: \(G_i = A_i \cdot B_i\)
    • Carry Propagate: \(P_i = A_i \oplus B_i\)
    • Carry Output: \(C_{i+1} = G_i + (P_i \cdot C_i)\)
  • Signed Addition/Subtraction: Executed using Two’s Complement arithmetic. Subtraction (\(A - B\)) is implemented by adding the two’s complement of \(B\) to \(A\): \[A - B = A + (\bar{B} + 1)\]
  • Overflow Condition: Overflow occurs during signed addition if two numbers of the same sign yield a result with the opposite sign.

Cache Mapping Techniques
  1. Direct Mapping: Each main memory block maps to exactly one fixed line in the cache defined by: \[\text{Cache Line} = (\text{Block Address}) \pmod{\text{Total Cache Lines}}\]
  2. Fully Associative Mapping: A memory block can be loaded into any available cache line. Tag matching requires simultaneous comparison across all lines.
  3. Set-Associative Mapping: Combines direct and associative approaches. Cache lines are grouped into sets (\(k\)-way). A block maps to a specific set, but can occupy any line within that set.

Virtual Memory, RAID & Storage Technologies

  • Virtual Memory: Uses hardware MMUs to present secondary disk storage to programs as continuous primary memory.
  • RAID (Redundant Array of Independent Disks):
    • RAID 0: Striping without fault tolerance. High performance.
    • RAID 1: Disk Mirroring. Complete data redundancy.
    • RAID 5: Block-level striping with distributed parity. High efficiency and fault tolerance.
  • Solid State Drives (SSD): Non-volatile flash memory storage devices using NAND gate arrays, offering lower latencies than mechanical hard drives.

Input/Output Organization & Interrupt Processing

  1. Programmed I/O: The CPU continuously polls an I/O module status register in a software loop, wasting processing cycles.
  2. Interrupt-Driven I/O: The CPU issues commands to the I/O module and continues executing other tasks. When the I/O module finishes, it triggers a hardware Interrupt Request (IRQ) signal. The CPU suspends the current process, pushes register context onto the stack, executes the corresponding Interrupt Service Routine (ISR), and resumes execution upon completion.
  3. Direct Memory Access (DMA): A dedicated DMA Controller takes control of system buses to transfer data blocks directly between memory and peripherals, bypassing the CPU to reduce overhead.

Instruction Pipelining & Pipeline Hazards

Pipelining executes multiple instructions concurrently across overlapping stages: Fetch (F), Decode (D), Execute (E), Memory Access (M), Writeback (W).

Clock Cycles ->   1    2    3    4    5    6    7
Instruction 1:  [ F ][ D ][ E ][ M ][ W ]
Instruction 2:       [ F ][ D ][ E ][ M ][ W ]
Instruction 3:            [ F ][ D ][ E ][ M ][ W ]
Pipeline Hazards & Mitigations
  1. Data Hazard: Occurs when an instruction depends on the result of an earlier instruction that has not yet completed writeback.
    • Code Example: ADD EAX, EBX MOV ECX, [EAX] (Data dependency on EAX)
    • Solutions: Operand Forwarding (routing hardware paths directly from execution stages), compiler stall insertion, or register renaming.
  2. Control Hazard (Branch Hazard): Occurs when branch or jump instructions alter the instruction sequence, making pre-fetched instructions invalid.
    • Code Example: CMP EAX, 39H JLE DOWN (Target address unknown until execution)
    • Solutions: Dynamic Branch Prediction, Branch Target Buffers (BTB), and Delayed Branching.
  3. Structural Hazard: Hardware resource conflicts when multiple pipelined stages require the same physical unit (e.g., memory port) simultaneously.
    • Solutions: Separating L1 Cache into distinct Instruction and Data Caches (Harvard Architecture).

  1. SISD (Single Instruction, Single Data): Conventional single-core CPU executing one instruction stream on one data stream.
  2. SIMD (Single Instruction, Multiple Data): A single instruction controls multiple parallel processing elements operating on vector array data simultaneously (e.g., modern GPUs and vector extensions).

  4. MIMD (Multiple Instruction, Multiple Data): Multiple independent processors execute different instruction streams on different data sets simultaneously (e.g., Multi-core processors and Symmetric Multiprocessing [SMP] systems).
  5. Superscalar Execution: Employs multiple parallel execution pipelines inside a single CPU, allowing multiple instructions to issue during a single clock cycle.

%endmacro

    ; IMUL performs signed multiplication.

    cqo

    ; Quotient is returned in RAX.
    ; Remainder is returned in RDX.

; Purpose: Read a signed decimal integer from standard input.

;   Output: RAX = -123

;
;   value = value * 10 + digit
;
; A leading minus sign is supported.

    ; Read up to 64 bytes from standard input.
    xor rax, rax                ; syscall 0 = read
    xor rdi, rdi                ; file descriptor 0 = stdin
    mov rsi, input_buf
    mov rdx, 64
    syscall

    ; RAX contains the number of bytes read.
    test rax, rax
    jle INVALID_INPUT

    mov rcx, rax                ; Number of characters read
    mov rsi, input_buf          ; Pointer to the input
    xor rax, rax                ; Accumulated numeric value
    xor r8, r8                  ; Sign flag: 0 = positive

    ; Check whether the first character is a minus sign.
    cmp byte [rsi], '-'
    jne READ_DIGITS

    mov r8, 1                   ; Mark the number as negative
    inc rsi
    dec rcx


READ_DIGITS:
    ; Stop when all characters have been processed.
    test rcx, rcx
    jz FINISH_READ

    movzx rbx, byte [rsi]

    ; Ignore the line-feed character generated by Enter.
    cmp bl, 10
    je FINISH_READ

    ; Convert ASCII '0' through '9' into numeric digits.
    cmp bl, '0'
    jb INVALID_INPUT
    cmp bl, '9'
    ja INVALID_INPUT

    sub bl, '0'

    ; Multiply the current value by 10.
    imul rax, rax, 10

    ; Add the new digit.
    movzx rbx, bl
    add rax, rbx

    inc rsi
    dec rcx
    jmp READ_DIGITS


FINISH_READ:
    ; Apply the negative sign if one was entered.
    test r8, r8
    jz READ_DONE
    neg rax

; This simple teaching version does not display an error.

    mov rdi, 1                  ; Exit status 1
    syscall

; PROCEDURE: PRINT_DECIMAL
; Purpose: Display the signed integer stored in RAX.
;
; Example:
;   RAX = 123  -> displays 123
;   RAX = -45  -> displays -45
;
; Repeatedly divides the number by 10 to extract decimal
; digits. Digits are generated in reverse order, so they
; are stored backward in the output buffer.
; ============================================================

    ; Save the number being printed.
    mov r8, rax

    ; Point RSI to the end of the output buffer.
    mov rsi, output_buf
    add rsi, 32

    ; RDI will count the characters to display.
    xor rdi, rdi

    ; Handle zero separately because dividing zero produces
    ; no digits in the normal extraction loop.
    test r8, r8
    jnz CHECK_SIGN

    dec rsi
    mov byte [rsi], '0'
    inc rdi
    jmp DISPLAY_NUMBER


CHECK_SIGN:
    ; Check whether the number is negative.
    test r8, r8
    jns EXTRACT_DIGITS

    ; Convert the magnitude to an unsigned value.
    ; This also handles the most-negative signed 64-bit value.
    mov rax, r8
    neg rax
    mov r8, rax

    ; Remember that a minus sign must be displayed.
    mov r9, 1
    jmp START_EXTRACTION


EXTRACT_DIGITS:
    xor r9, r9                  ; Positive number: no minus sign


START_EXTRACTION:
    mov rax, r8
    mov rbx, 10                 ; Decimal base


DECIMAL_LOOP:
    ; Divide the unsigned magnitude by 10.
    ; RAX = quotient, RDX = remainder (next digit).
    xor rdx, rdx
    div rbx

    ; Convert the remainder (0-9) to an ASCII character.
    add dl, '0'

    ; Store digits from right to left.
    dec rsi
    mov [rsi], dl
    inc rdi

    ; Continue until the quotient becomes zero.
    test rax, rax
    jnz DECIMAL_LOOP

    ; Add the minus sign before the digits if needed.
    test r9, r9
    jz DISPLAY_NUMBER

    dec rsi
    mov byte [rsi], '-'
    inc rdi


DISPLAY_NUMBER:
    ; Write the generated characters to standard output.
    mov rax, 1                  ; syscall 1 = write
    mov rdx, rdi                ; Number of characters
    mov rdi, 1                  ; Standard output
    syscall
    ret

; EXIT_PROGRAM
; Purpose: Terminate the program.
; ============================================================

    mov rax, 60
    xor rdi, rdi
    syscall

2️⃣ Lab Assignment 2: Binary to Hexadecimal and Hexadecimal to Binary Conversion

Program Purpose

This program converts a binary bit-string into its hexadecimal equivalent, or a hexadecimal string into its grouped 4-bit binary equivalent. It uses direct Linux 64-bit system calls and does not depend on the C library.

Theory & Logic Breakdown

Binary and hexadecimal are directly related because each hexadecimal digit represents exactly 4 binary bits:

Hex Digit Binary Hex Digit Binary
0 0000 8 1000
1 0001 9 1001
2 0010 A 1010
3 0011 B 1011
4 0100 C 1100
5 0101 D 1101
6 0110 E 1110
7 0111 F 1111

Binary to Hexadecimal:

For each input character:

\[ \text{value} = (\text{value} \times 2) + \text{bit} \]

Equivalently, the program shifts the accumulator left by one bit and sets the lowest bit only when the input character is '1'. After parsing, the value is printed as hexadecimal by extracting 4-bit nibbles from left to right. Leading zero nibbles are suppressed.

Hexadecimal to Binary:

Each hexadecimal character is converted into a numeric nibble:

  • '0'–'9' → subtract '0'
  • 'A'–'F' → subtract ('A' - 10)
  • 'a'–'f' → subtract ('a' - 10)

The nibble is then expanded into exactly four ASCII binary characters and printed. A space is inserted between groups for readability.

3️⃣ Lab Assignment 3: Multiplication using Successive Addition & Add-and-Shift

Program Purpose

This program accepts two unsigned decimal integers and calculates their product using two classical multiplication methods:

  1. Successive Addition
  2. Add-and-Shift Multiplication

It displays the final product in hexadecimal, binary, and decimal formats.

Theory & Logic Breakdown

1. Successive Addition

For unsigned integers \(A\) and \(B\):

\[ A \times B = \underbrace{A + A + \cdots + A}_{B \text{ times}} \]

The program stores the multiplicand in no1 and the multiplier in no2. It repeatedly adds no1 to RBX and decrements no2 until it becomes zero.

This method is simple but inefficient: multiplying \(A\) by a large \(B\) requires approximately \(B\) additions.

2. Add-and-Shift Multiplication

The add-and-shift method examines each bit of the multiplier \(Q\). If the current least-significant bit of \(Q\) is 1, the multiplicand \(B\) is added to the accumulator \(A\). The combined \(A:Q\) pair is then shifted right by one bit.

For a 64-bit multiplier, the algorithm executes 64 iterations.

\[ \text{Product} = \sum_{i=0}^{63} Q_i \times B \times 2^i \]

Algorithm Diagram

graph TD
    Start([Start Multiplication]) --> Init[Read Multiplicand B and Multiplier Q<br/>Set A = 0, Count = 64]
    Init --> CheckQ{LSB of Q == 1?}
    CheckQ -- Yes --> Add[A = A + B]
    CheckQ -- No --> Shift[Shift A:Q Right by 1 Bit]
    Add --> Shift
    Shift --> Dec[Count = Count - 1]
    Dec --> CheckCount{Count == 0?}
    CheckCount -- No --> CheckQ
    CheckCount -- Yes --> Result[Product is in Q]
    Result --> Display[Display Hex, Binary, and Decimal Result]
    Display --> End([End])

Worked Example: \(7 \times 9\)

Multiplicand \(B = 7 = 0111_2\)
Multiplier \(Q = 9 = 1001_2\)
Accumulator \(A = 0\)

Step \(Q\) LSB Operation \(A\) \(Q\)
Initial — Initialize 0000 1001
1 1 \(A = A + B = 0 + 7\) 0111 1001
1 — Shift \(A:Q\) right 0011 1100
2 0 Shift \(A:Q\) right 0001 1110
3 0 Shift \(A:Q\) right 0000 1111
4 1 \(A = A + B = 0 + 7\) 0111 1111
4 — Shift \(A:Q\) right 0011 1111

Final lower product register \(Q = 00111111_2 = 63\).

Therefore:

\[ 7 \times 9 = 63 \]

Step-by-Step Program Execution

  1. The program displays the multiplication menu and reads the user’s choice.

  2. For either method, it reads the multiplicand and multiplier as decimal ASCII strings.

  3. PARSEDECIMAL converts the ASCII digits into an unsigned 64-bit value using:

    \[ \text{value} = (\text{value} \times 10) + \text{digit} \]

  4. Successive Addition: repeatedly adds the multiplicand to RBX until the multiplier becomes zero.

  5. Add-and-Shift: checks the multiplier LSB, adds the multiplicand when required, shifts the accumulator and multiplier, and repeats for 64 bits.

  6. DISPLAYALLTHREE prints the resulting product as:

    • 16-digit hexadecimal
    • 64-bit binary
    • unsigned decimal

Program Purpose

This program performs common string operations on user-entered strings using 64-bit NASM assembly and direct Linux system calls. It supports length, copy, reverse, comparison, concatenation, palindrome checking, and substring searching.

Theory & Logic Breakdown

A string is stored as a sequence of ASCII bytes. The program does not rely on null termination; instead, it stores the actual length of each input string after trimming trailing newline (10) and carriage-return (13) characters.

Length:

\[ \text{Length} = \text{bytes read} - \text{trailing control characters} \]

Copy:

rep movsb copies RCX bytes from the memory address in RSI to the address in RDI, incrementing both pointers after every byte.

Reverse:

The source pointer initially points to the last character:

\[ \text{Last Character Address} = \text{String Base} + \text{Length} - 1 \]

The program copies each character into the destination buffer while decrementing the source pointer and incrementing the destination pointer.

Comparison:

Two strings are equal only when:

  1. Their lengths are equal.
  2. Every corresponding byte matches.

repe cmpsb repeatedly compares bytes while they are equal and stops at the first mismatch or after RCX bytes.

Palindrome:

A string is a palindrome if:

\[ S_i = S_{n-1-i} \quad \text{for all } 0 \le i < n \]

The program reverses the input into string3, then compares the original and reversed strings.

Substring Search:

For a source string of length \(m\) and pattern of length \(n\), the program checks at most \(m-n+1\) starting positions. At each position, it compares \(n\) bytes using repe cmpsb.

Program Purpose

This program calculates the roots of a quadratic equation:

\[ ax^2 + bx + c = 0 \]

using the quadratic formula:

\[ X_{1,2} = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a} \]

It uses the x87 floating-point unit, conceptually corresponding to the 80387 math coprocessor, along with printf and scanf from the C library. [5]

Condition Result
\(a = 0\) Not a quadratic equation; program displays an error
\(D = b^2 - 4ac > 0\) Two distinct real roots
\(D = 0\) One repeated real root: \(x = -b / 2a\)
\(D < 0\) No real roots; roots are complex

FPU Register Stack

The x87 FPU provides eight 80-bit registers organized as a stack. ST(0) is the top of stack.

        +----------------------+
ST(0)   | Current value        |
        +----------------------+
ST(1)   | Previous value       |
        +----------------------+
ST(2)   | Older value          |
        +----------------------+
        | ...                  |
        +----------------------+
ST(7)   | Bottom of stack      |
        +----------------------+
Instruction Operation
FINIT Initializes and resets the FPU
FLD Pushes a floating-point value onto the stack
FMUL Multiplies floating-point values
FSUB Subtracts floating-point values
FCHS Changes the sign of ST(0)
FIMUL Multiplies ST(0) by an integer memory operand
FTST Compares ST(0) with zero
FNSTSW AX / SAHF Transfers FPU status flags into CPU flags
FSQRT Computes square root of ST(0)
FSTP Stores ST(0) to memory and pops the stack

  1. Calculate \(4ac\):

  1. Since \(D > 0\), calculate:

  1. Calculate both roots:

    call scanf
%endmacro

; ============================================================
; MACRO: WRITE_FLOAT
; Purpose: Display a double-precision value using printf.
;
; Parameters:
;   %1 = Format string address
;   %2 = 64-bit floating-point memory location
; ============================================================
%macro WRITE_FLOAT 2
    mov rax, 1
    mov rdi, %1
    movsd xmm0, %2
    call printf
%endmacro

main:
    ; Establish stack frame and ensure 16-byte boundary alignment
    push rbp
    mov rbp, rsp

    ; --------------------------------------------------------
    ; 1. Read coefficients a, b, and c
    ; --------------------------------------------------------
    WRITE_STR fmt_str, msg_prompt
    READ_FLOAT fmt_float, coeff_a
    READ_FLOAT fmt_float, coeff_b
    READ_FLOAT fmt_float, coeff_c

    ; --------------------------------------------------------
    ; 2. Initialize 80387 FPU and validate coefficient 'a'
    ; --------------------------------------------------------
    finit

    ; Check whether coefficient 'a' is zero (a != 0 required)
    fld qword [coeff_a]
    ftst
    fnstsw ax
    sahf
    fstp st0

    je INVALID_A

    ; --------------------------------------------------------
    ; 3. Calculate discriminant: D = b^2 - 4ac
    ; --------------------------------------------------------
    ; Step A: Calculate b^2
    fld qword [coeff_b]
    fmul st0, st0
    fstp qword [term_b2]

    ; Step B: Calculate 4ac
    fld qword [coeff_a]
    fmul qword [coeff_c]
    mov word [temp_word], 4
    fimul word [temp_word]
    fstp qword [term_4ac]

    ; Step C: Calculate D = b^2 - 4ac
    fld qword [term_b2]
    fsub qword [term_4ac]
    fstp qword [term_disc]

    ; --------------------------------------------------------
    ; 4. Check discriminant value
    ; --------------------------------------------------------
    fld qword [term_disc]
    ftst
    fnstsw ax
    sahf
    fstp st0

    jb NO_REAL_ROOTS
    je SINGLE_ROOT

    ; --------------------------------------------------------
    ; 5. Calculate square root of discriminant
    ; --------------------------------------------------------
    fld qword [term_disc]
    fsqrt
    fstp qword [term_sqrt]

    ; --------------------------------------------------------
    ; 6. Calculate -b and 2a
    ; --------------------------------------------------------
    ; Step A: Calculate -b
    fld qword [coeff_b]
    fchs
    fstp qword [term_neg_b]

    ; Step B: Calculate 2a
    fld qword [coeff_a]
    mov word [temp_word], 2
    fimul word [temp_word]
    fstp qword [term_2a]

    ; --------------------------------------------------------
    ; 7. Calculate and display both roots
    ; --------------------------------------------------------
    WRITE_STR fmt_str, msg_roots

    ; Root 1 = (-b + sqrt(D)) / 2a
    fld qword [term_neg_b]
    fadd qword [term_sqrt]
    fdiv qword [term_2a]
    fstp qword [root1]

    WRITE_FLOAT fmt_root, [root1]

    ; Root 2 = (-b - sqrt(D)) / 2a
    fld qword [term_neg_b]
    fsub qword [term_sqrt]
    fdiv qword [term_2a]
    fstp qword [root2]

    WRITE_FLOAT fmt_root, [root2]

    jmp EXIT_PROGRAM

; ============================================================
; SINGLE_ROOT
; Purpose: Discriminant is zero (x = -b / 2a).
; ============================================================
SINGLE_ROOT:
    ; Calculate -b
    fld qword [coeff_b]
    fchs
    fstp qword [term_neg_b]

    ; Calculate 2a
    fld qword [coeff_a]
    mov word [temp_word], 2
    fimul word [temp_word]
    fstp qword [term_2a]

    ; Calculate the single root
    fld qword [term_neg_b]
    fdiv qword [term_2a]
    fstp qword [root1]

    WRITE_STR fmt_str, msg_roots
    WRITE_FLOAT fmt_root, [root1]

    jmp EXIT_PROGRAM

; ============================================================
; NO_REAL_ROOTS
; Purpose: Discriminant is negative; report no real roots.
; ============================================================
NO_REAL_ROOTS:
    WRITE_STR fmt_str, msg_no_real
    jmp EXIT_PROGRAM

; ============================================================
; INVALID_A
; Purpose: Report coefficient 'a' cannot be zero.
; ============================================================
INVALID_A:
    WRITE_STR fmt_str, msg_invalid_a
    jmp EXIT_PROGRAM

; ============================================================
; EXIT_PROGRAM
; Purpose: Restore stack frame and return exit status 0.
; ============================================================
EXIT_PROGRAM:
    mov rsp, rbp
    pop rbp

    xor rax, rax
    ret

section .note.GNU-stack noalloc noexec nowrite progbits
